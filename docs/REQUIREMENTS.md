# V0.2 需求冻结

## 核心用户流程

1. 两台设备安装同一 APK，位于同一局域网。
2. 发送端可以在 App 内选文件，也可以从 Android 系统分享表进入；MVP 重点保证后者。
3. App 默认通过二维码交换 IP、端口和短期连接码；自动发现与手动输入作为兜底。
4. 发送端选择目标设备。
5. 接收端显示发送方、文件名、大小并人工确认。
6. 传输使用流式 I/O；断网后可基于已接收字节继续。
7. 完成后接收端重新计算 SHA-256；仅当与发送端一致时成功落盘。
8. 文件进入 `Download/LanShare`。

## 交互约束

- 手机首屏只服务分享：选择文件、文件摘要、目标设备、发送；页面本身不滚动。
- 手机的扫码/本机二维码位于独立连接页；文件清单、手动连接和传输详情使用内部可滚动弹层。
- 宽屏/车机同时展开分享与连接双栏，不显示无意义的底部导航。
- 传输状态仅在存在任务时浮现，收起态展示当前文件、速度和完成文件数。
- IP、端口、SHA-256 等技术信息不得常驻分享首页。

## 性能要求

- 正常无重试路径由发送文件流同步计算 SHA-256，不得在发送前完整预扫文件。
- 接收端写入 `.part` 时同步计算 SHA-256；仅在流式摘要不可复用时回退完整重扫。
- UI 进度更新节流，避免按每个缓冲块触发界面重组。

## 明确不做

- 音乐在线播放/DLNA。
- 云服务器、账号、广告、推荐。
- 互联网穿透。
- iOS 客户端。
