# MVP 真机验收计划

必须至少使用两台 Android 10+ 真机；“编译通过”不能代替真实链路验收。

## A. 基础

- [ ] `:app:assembleDebug` PASS。
- [ ] 两台设备均安装、启动，无 crash。
- [ ] 手机竖屏 UI 无遮挡。
- [ ] 横屏/车机宽屏呈双栏，无关键操作被裁切。
- [ ] 手机分享首页不需要页面滚动即可完成“选择文件 -> 选择设备 -> 发送”。
- [ ] 文件清单与传输详情仅在弹层内部滚动，关闭后返回原操作位置。

## B. 分享入口

- [ ] 文件管理器长按单文件 -> 分享 -> LocalShare，文件名/大小正确。
- [ ] 多文件 ACTION_SEND_MULTIPLE 正确列出。
- [ ] App 内“选择文件”可一次选择多个文件并列入待发送列表。
- [ ] 不依赖 filesystem path；来自相册/Downloads provider 的 content URI 可读。

## C. 发现与确认

- [ ] 同 Wi-Fi 自动发现。
- [ ] 接收端二维码包含当前真实 IP、动态服务端口和当前 4 位连接码。
- [ ] 发送端授予相机权限后可扫描二维码，扫码后自动选中正确设备。
- [ ] 非 LanShare、版本错误、非法 IP/端口/连接码二维码被拒绝且不新增设备。
- [ ] 手机热点场景自动发现；若失败，手动 IP 可发送。
- [ ] 端口被占用时服务自动切换备用端口，发现广播与手动地址均使用真实端口。
- [ ] 手动地址缺少、非数字或非 4 位访问口令时，界面拒绝提交。
- [ ] 接收面板“打开接收目录”调用系统文件管理器定位到 `Download/LanShare`；必要时可回退到目录选择器。
- [ ] 接收端拒绝后发送端明确失败。
- [ ] 未确认前不写正式 Download 文件。

## D. 正常传输

- [ ] 10 KB、10 MB、500 MB 文件均成功。
- [ ] 接收文件位于 `Download/LanShare`。
- [ ] 发送端原文件 SHA-256 == 接收端最终文件 SHA-256。
- [ ] 传输浮层展示当前文件、实时速度、ETA、已完成文件数/总文件数。
- [ ] 无断网路径不执行发送前整文件 SHA 扫描；接收端不在 complete 后重复扫描 `.part`。

## E. 断点续传

- [ ] 传输 500 MB 文件至 30%-70% 时关闭 Wi-Fi 10 秒。
- [ ] 恢复网络后重试同一 session，不从 0 开始，服务端 offset > 0。
- [ ] 最终 hash 一致。

## F. 失败安全

- [ ] 人工篡改 `.part` 后 complete 返回 422，Downloads 不出现“成功文件”。
- [ ] 空间不足时明确失败，不显示成功。
- [ ] 对方 App 被杀/断网，发送端不假成功。
- [ ] 文件重名时 MediaStore 正常生成可用项，不覆盖未知原文件。

## 证据要求

每一条 PASS 保存：设备型号/Android 版本、操作步骤、日志或截图、最终 hash。Agent 不得用单测绿替代真实传输证据。

## 自动化验证

- `python3 scripts/static_verify.py`
- `./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug`
- `docker build --progress=plain -t lanshare-verify .`

自动化通过仍不能替代本计划要求的双机真机证据。
